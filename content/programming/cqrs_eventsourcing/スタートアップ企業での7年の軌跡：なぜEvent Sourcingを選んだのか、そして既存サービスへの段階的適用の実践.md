# Event Sourcing を採用した理由
モデリング・集約の精査が難しかったから。

Event Sourcing では下記のステップで実現ができて簡単でわかりやすい

- 具体的な事実に着目する
- 事実ごとに制約をかける
- 事実の結果として状態を再現する

## 疑問
> 集約の精査が難しかったから Event Sourcing で事実を記録する方向にシフトして解決しようとした

Event Sourcing ではドメインイベントを記録していくわけだが、ドメインイベントの記録というのは集約単位での内部制約があった上でなされるはず。
つまりイベントの記録より先に集約としての正しさが求められる。
例えば 「ファイル管理」に対して `AddFile -> RenameFile -> DeleteFile` という順番で記録ドメインイベントを受け入れられるが `DeleteFile -> AddFile -> RenameFile` のようにはできない。
要は何が言いたいのかというと、Event Sourcing に移行したとしても集約の精査の難易度は変わらないのではないか？
